The submission contract

If I cannot run it from a clean machine, it does not count
your-repo/
submission.yaml   # model, stack, key params
serve.sh          # uv sync + start server
pyproject.toml    # dependencies
uv.lock           # pinned, reproducible
JOURNAL.md        # one entry per round
Dockerfile        # optional: used if present
  • ·Model: any open-weight model that fits in 16 GB with KV cache for 64 concurrent requests.
  • ·Stack: anything — vLLM, SGLang, llama.cpp, TensorRT-LLM, your own kernels.
serve.sh · examplebash
#!/usr/bin/env bash
set -euo pipefail
uv sync --frozen
exec uv run vllm serve Qwen/Qwen3-4B-AWQ \
  --served-model-name submission \
  --host 0.0.0.0 --port 8000 \
  --max-num-seqs 64 \
  --gpu-memory-utilization 0.92

Fixed: port 8000, model name submission, OpenAI-compatible /v1/chat/completions with streaming. Everything else is yours to change.

The contract is strict on purpose: I must be able to literally clone your repository and run it. Pin everything (uv.lock). Do not download things at runtime that are not pinned. The model and the stack are free choices and may change from round to round — that is part of your story. A Dockerfile is optional; if it exists, the judge builds and runs it instead of serve.sh. The example uses vLLM with an AWQ-quantized 4B model; it is an example, not a recommendation.
