  • ·Model: any open-weight model that serves 64 × (512 + 256) tokens at once in 16 GB.
  • ·Stack: anything — vLLM, SGLang, llama.cpp, TensorRT-LLM, your own kernels.
serve.sh · examplebash
#!/usr/bin/env bash
set -euo pipefail
uv sync --frozen
exec uv run --frozen vllm serve \
  Qwen/Qwen2.5-3B-Instruct \
  --served-model-name submission \
  --host 0.0.0.0 --port 8000 \
  --dtype half --max-model-len 4096 \
  --gpu-memory-utilization 0.90

Fixed: port 8000, model name submission, streaming /v1/chat/completions that honours max_tokens and ignore_eos and takes 4096-token requests. Start from submission-template/ in the course repo.

The contract is strict on purpose: I must be able to literally clone your repository and run it. Pin everything (uv.lock). Do not download things at runtime that are not pinned. The model and the stack are free choices and may change from round to round — that is part of your story. A Dockerfile is optional; if it exists, the judge builds and runs it instead of serve.sh. The example is the reference submission itself (Qwen2.5-3B-Instruct on plain vLLM, FP16) — the round-1 bars were measured with it. It is a starting point, not a recommendation. The server must honour max_tokens and ignore_eos: the speed benchmark asks for exactly 256 tokens, and a server that stops early does not get a faster score — it fails the output-length check.
