Tensor role predicts desired placement

But software does not control every hit

Long-lived

  • weights: device memory, reused by kernels
  • KV cache: device memory, grows per request
  • allocator pools: reserved for reuse

Short-lived / tiled

  • activations and workspace
  • L2-resident reused lines when lucky
  • shared-memory tiles and registers
“Stored in HBM” does not mean every access necessarily reaches HBM; caches mediate actual traffic.

Reuse is the bridge from bytes to operations

The performance lever
DATA REUSE
Perform more useful operations before the same data must be fetched again from a slower memory level.

Batching reuses weights across token rows; tiling reuses blocks on chip; fusion keeps intermediate values closer to compute.

Reuse does not reduce model semantics. It reorganizes execution and data movement.

Equal bytes can produce unequal transactions

Access pattern matters

Friendly access

Neighboring threads access neighboring addresses; transactions are coalesced and useful payload is high.

Hostile access

Scattered or misaligned accesses request extra memory transactions and waste transferred bytes.

The lesson is not to hand-optimize CUDA today; it is to know why nominal tensor size alone does not equal observed traffic.

Fusion removes materialization boundaries

Same math, fewer round trips

Fusion may increase register pressure or reduce flexibility. It is a trade-off, not a universal free win.

FlashAttention is an IO algorithm

Exact attention, tiled differently

Naïve mental model

Materialize the (S\times S) score matrix in device memory, then read it again for softmax and value aggregation.

IO-aware model

Tile Q/K/V and maintain online softmax statistics so less intermediate state travels to HBM.

Cite Dao et al.: the result is exact attention. Avoid claiming it changes the quadratic arithmetic of dense attention.

Less attention IO does not erase generation physics

Scope the optimization
Overclaim

“FlashAttention solves long-context inference.”

Autoregressive steps remain serial; KV state still grows; decode still reads history; weights, MLPs, capacity, and scheduling remain.
Optimization claims need a denominator: which phase, which kernel, which context, and which end-to-end metric?
