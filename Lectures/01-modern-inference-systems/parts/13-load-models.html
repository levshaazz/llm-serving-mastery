Concurrency is not an arrival process

Workload

Closed loop

A fixed number of clients sends the next request after the previous one completes.

Useful for saturation sweeps; slow service automatically reduces offered load.

Open loop

Requests arrive according to an external rate, independent of completion.

Closer to demand spikes; exposes queue growth and overload.

This distinction prevents coordinated omission. A closed-loop client waits when the server is slow, so it may under-sample the worst waiting times. We will use both later and label them.
