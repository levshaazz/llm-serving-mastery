Inference is computation; serving is coordination

Do not collapse the layers

Inference

  • tokenize inputs
  • run model forward passes
  • sample next tokens
  • stop on a termination rule

Serving

  • authenticate, admit, queue, schedule
  • stream, cancel, retry, rate-limit
  • load, warm, drain, roll back
  • measure promises by tenant/workload

Admission control protects work already accepted

Before the queue
ADMISSION
Decide whether a request may consume scarce serving capacity now.

Inputs: tenant quota, deadline, estimated token demand, queue state, worker health. Outputs: accept, defer, route elsewhere, or reject with a retryable/non-retryable signal.

The scheduler chooses progress, not just order

Inside the engine
SCHEDULER
Select which sequences enter the next model step and which state remains resident.

A policy trades TTFT, decode continuity, throughput, fairness, memory pressure, and deadline risk. “FIFO” names only one dimension.

Same model, different operating problem

Online vs offline

Online

  • arrivals are externally timed
  • per-request deadlines matter
  • streaming and cancellation matter
  • capacity headroom buys reliability

Offline batch

  • backlog is controlled
  • completion horizon dominates
  • reordering is often acceptable
  • high utilization can be rational

Common misconception

“We put FastAPI around it”
What people think

“The endpoint is concurrent, therefore the model service is concurrent.”

Async HTTP can accept many sockets while all requests wait behind one serialized model path. Concurrency at the gateway says nothing about scheduling inside the engine.

Streaming changes the contract, not the total work

Partial results

It introduces

  • chunk framing and buffering
  • disconnect propagation
  • partial-response semantics

Cancellation must cross every boundary

Stale work is still work
CANCEL
A client disconnect is useful only if it removes queued work, stops future decode steps, and releases request state.

Measure cancellation lag: disconnect timestamp → scheduler removal → memory release.

Alive is not ready

Lifecycle semantics

Process alive

The event loop responds. Weights may still be loading; kernels may still be warming; no request should arrive.

Service ready

The intended model revision is resident, warmup passed, dependencies are reachable, and admission is enabled.
