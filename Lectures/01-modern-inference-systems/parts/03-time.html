Prefill converts the prompt into reusable state

Phase 1
PREFILL
Process the input tokens, produce the first next-token distribution, and populate per-request attention state.

Its duration depends on input length, batch composition, model/runtime, hardware, and any prefix reuse—not merely “prompt size”.

Decode advances every unfinished sequence

Phase 2
DECODE
Repeatedly generate a token, update request state, test stopping rules, and stream progress.

The user experiences cadence; the scheduler experiences a changing set of live sequences.

State the denominator
Ambiguous report

“TPOT = 22 ms.”

A percentile needs a population

p99 of what?

Valid statement

p99 TTFT among all admitted chat requests in region A during 10:00–10:15, with failures reported separately.

Invalid shortcut

“Latency p99 = 1.2 s” with no phase, route, tenant, window, sampling rule, or failure treatment.

Trace durations; do not subtract unrelated clocks

Measurement hygiene

Safe

  • monotonic clock within one process
  • span duration recorded by owner
  • synchronized clocks with known error

Unsafe

  • client wall clock minus server wall clock
  • mix milliseconds and seconds
  • derive queue time from rounded logs
