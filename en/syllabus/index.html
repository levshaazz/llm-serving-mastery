LLM Serving Mastery: vLLM, Multi-GPU, and Production Deployment

Dates TBA

Train an engineer who can optimize an LLM, stand up a high-performance OpenAI-compatible API on vLLM, serve dozens to hundreds of concurrent clients from a single instance, deploy the system on multiple GPUs and Kubernetes, and operate it as LLMOps.

Instructor
Albert Nasybullin
Level
Intermediate → Advanced
Audience
ML / LLM engineers, MLOps, DevOps and backend engineers
Format
15 topics · lectures + hands-on seminars · multi-GPU and Kubernetes labs included when the infrastructure block begins
Workload
Baseline ≈ 10–14 hours per week; advanced and leaderboard track ≈ 16–20 hours. Material that does not fit the contact session remains required guided self-study; expect ≈ 180–300 hours in total.

Learning outcomes

  • Explain where inference time and memory go — prefill vs decode, the KV cache, memory bandwidth — and predict the bottleneck before measuring it.
  • Quantize a model and defend the speed / memory / quality trade-off with numbers.
  • Serve a model through vLLM's OpenAI-compatible API and tune it for a given concurrency profile.
  • Benchmark a serving stack honestly: throughput, TTFT, TPOT, p95, failures — under 1 to 128+ concurrent clients.
  • Package inference in Docker and design multi-GPU and Kubernetes deployments: tensor parallelism, GPU Operator, HPA.
  • Operate it: metrics, dashboards, alerts and cost per million tokens.

Prerequisites

  • Python — confident; asyncio basics help (we write load generators).
  • Linux command line and git — you will ship a repository every week (uv is shown in seminar 1).
  • Deep-learning basics — what a transformer forward pass and a token are; PyTorch at the reading level.
  • HTTP / REST basics — requests, JSON, streaming responses.
  • Accounts: GitHub, Hugging Face, Google (for Colab). No prior Docker or Kubernetes needed — taught in the course.

Detailed study plan

15 topics · all remain in scope · overflow becomes guided self-study, not deleted content

1. Modern LLM inference systems & production challenges

Contact-session coreServing lifecycle, prefill/decode, SLOs, capacity and the course measurement contract.
Required self-studySet up uv, Git, Colab GPU and the submission repository; reproduce the baseline run.
Advanced trackTrace one OpenAI-compatible streaming request end to end and document every boundary.

2. Inference bottlenecks: KV cache, memory hierarchy, autoregression

Contact-session coreAutoregression, KV-cache sizing, memory hierarchy, roofline reasoning and profiler literacy.
Required self-studyProfile prefill and decode separately; reconcile measured memory and latency with a hand calculation.
Advanced trackBuild a small roofline model and test where batch size changes the active bottleneck.

3. Model quantization for production

Contact-session coreWeight and activation formats, calibration, weight-only vs weight-activation quantization, quality risk.
Required self-studyQuantize one model, benchmark memory/speed/quality, and explain hardware-specific kernel support.
Advanced trackCompare AWQ/GPTQ/FP8/NVFP4 assumptions and reproduce one surprising regression.

4. vLLM architecture & OpenAI-compatible serving

Contact-session corevLLM engine architecture, scheduler, OpenAI protocol, streaming and production configuration surfaces.
Required self-studyLaunch a pinned vLLM service and validate protocol, model metadata, streaming and failure responses.
Advanced trackMap API parameters to engine behavior and identify parameters the backend ignores or rewrites.

5. PagedAttention & continuous batching

Contact-session corePagedAttention, block allocation, fragmentation, continuous batching and scheduler trade-offs.
Required self-studyCompare pipeline and vLLM under controlled prompts, outputs and concurrency; explain the gap.
Advanced trackInstrument block pressure and relate queueing events to KV-cache occupancy.

6. High-concurrency serving: one instance, 50–200+ clients

Contact-session coreLoad models, open vs closed loop traffic, throughput/TTFT/TPOT tails, backpressure and saturation.
Required self-studyRun 8/32/64/128-client experiments with warm-up, errors and confidence-aware interpretation.
Advanced trackDesign an arrival process that resembles a real product and compare it with fixed concurrency.

7. Tuning vLLM parameters for different concurrency levels

Contact-session coreParameter interactions: max_num_seqs, batched tokens, memory utilization, chunked prefill and prefix caching.
Required self-studyPerform a bounded search, keep raw results, and choose a configuration for an explicit SLO.
Advanced trackModel the Pareto frontier and explain why the fastest point is not always the production point.

8. Production inference APIs: FastAPI + vLLM

Contact-session coreAPI contracts, cancellation, timeouts, admission control, quotas, validation, streaming and observability.
Required self-studyBuild a thin FastAPI gateway with request IDs, bounded queues, error mapping and streaming cancellation.
Advanced trackThreat-model abuse, prompt size, disconnects and retry storms; test at least two failure modes.

9. Docker for LLM inference

Contact-session coreGPU container runtime, image layers, immutable dependencies, model artifacts, security and startup economics.
Required self-studyProduce a lean pinned image, run it with GPU isolation and record cold/warm startup behavior.
Advanced trackCreate an SBOM and evaluate cache, driver and CUDA compatibility failure scenarios.

10. Multi-GPU inference: tensor parallelism

Contact-session coreTensor/pipeline/data parallelism, collectives, topology, communication cost and scaling efficiency.
Required self-studyRun 2- and 4-GPU configurations and explain throughput, latency, memory and interconnect effects.
Advanced trackPredict the useful scaling limit for two model sizes before measuring it.

11. Kubernetes for LLM serving: GPU Operator & Helm

Contact-session coreKubernetes GPU scheduling, device plugins, GPU Operator, Helm releases, storage and rollout safety.
Required self-studyInstall or use the provided cluster, deploy a pinned chart, observe scheduling and perform rollback.
Advanced trackDiagnose one deliberately broken driver, resource or readiness configuration.

12. Advanced Kubernetes: single-pod concurrency & HPA

Contact-session coreMulti-GPU pods, replicas, topology constraints, autoscaling signals, disruption and graceful draining.
Required self-studyScale on serving metrics, test a node/pod failure and compare observed recovery with the capacity model.
Advanced trackEvaluate HPA stability under bursty traffic and propose safeguards against oscillation.

13. LLMOps: observability, monitoring & cost control

Contact-session coreGolden signals for LLM serving, GPU/engine metrics, traces, alerts, SLO burn rates and token economics.
Required self-studyBuild dashboards and alerts that separate demand, queueing, model work and infrastructure failure.
Advanced trackCalculate cost per million useful tokens and identify the largest uncertainty in the estimate.

14. Fine-tuning in the serving pipeline: LoRA adapters in vLLM

Contact-session coreLoRA/QLoRA artifacts, adapter loading, multiplexing, isolation, batching effects and quality validation.
Required self-studyServe multiple adapters over one base model and measure switching, memory and mixed-traffic behavior.
Advanced trackDesign an adapter lifecycle with provenance, rollout and rollback guarantees.

15. Production best practices, cost optimization & trends

Contact-session coreArchitecture review, capacity/cost trade-offs, reliability patterns, evaluation drift and emerging serving paths.
Required self-studyDefend the full engineering story with reproducible evidence, limitations and an incident-ready runbook.
Advanced trackWrite a six-month improvement roadmap with decision triggers rather than trend predictions.

The leaderboard

  • Every round closes on Thursday at 23:59 Moscow time (MSK, UTC+3).
  • mark = 5 × min(1, S / S_bar) if every gate passes, else 0. Each round is worth 4% of the course grade: points = mark × 0.8.
  • The quality gates, speed bar S_bar and latency SLO are published before a round opens from a fresh, provenance-complete reference run using the same judge version. Legacy reconstructed bars are explicitly marked provisional and are not valid for grading.
  • Among submissions that cleared the bar (S ≥ S_bar): the top 10% get +2 Overdrive, the next 10% get +1 (rounded up; at least one student in each band; ties share).
  • Overdrive ≥ 10 after round 10 → the final exam is waived and credited at 40 / 50. The defense is still mandatory.
